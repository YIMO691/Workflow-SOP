# 按工作问题选择技能

这里推荐有助于本 SOP 的外部技能及方法，供按需采用；不是自动加载的技能包，也不是安装清单。每张推荐卡记录固定来源、读取范围、用途、输入、期望产物、限制与更新触发。当前均为方法阅读推荐，未完成目标项目中的安装或效果验证。

## 从当前问题进入

| 当前卡点 | 优先参考 | 应带回原任务的结果 |
|---|---|---|
| 想法模糊，双方理解不同 | [Matt：grill-me / grill-with-docs](MATT_POCOCK.md) | 当前目标、重要术语、已决取舍与剩余阻断 |
| 跨模块功能需要比较设计 | [spec-dev：requirement-analysis](REQUIREMENT_ANALYSIS.md)；[Superpowers：brainstorming](SUPERPOWERS.md) 二选一作为主要参考 | 方案理由、范围、可观察场景；已有决定不重问 |
| 规格清楚，不知道怎样拆工作 | [Matt：to-tickets](MATT_POCOCK.md) | 行为切片、真实依赖与验收关联 |
| 契约和上下文不足以支持实施 | [Superpowers：writing-plans](SUPERPOWERS.md) | 当前增量需要的接口、约束与检查；不替未来代码编实现 |
| 测试失败、修了几次仍不明原因 | [Superpowers：systematic-debugging](SUPERPOWERS.md) | 可复现症状、证据、待检验原因和有依据的修复 |
| 测试绿了却不知验收是否满足 | [Superpowers：verification-before-completion](SUPERPOWERS.md)；[Matt：tdd / code-review](MATT_POCOCK.md) | 对应当前版本的实际验证、规格与工程质量缺口 |
| 任务太大，方向仍不清楚 | [Matt：wayfinder](MATT_POCOCK.md) | 先解决哪些决定、尚未明确的范围和下一步；不是完成实现 |

这是问题入口，不是需要顺序运行的七个步骤。一个目的明确的小修复可直接按 SOP 做；不必先开访谈、调用规划器或安装整套插件。需求访谈、领域建模、规格和任务切分可以分别取用，但已足够的结果无需重做。

## 怎样开始使用

先看推荐卡的固定原文和已知差异。仅参考方法时，可在原任务补一段要求：

```text
按项目规则和本轮授权，参考 <推荐卡中的固定来源> 处理 <当前具体问题>。
输入是 <需求与现有约定>；结果回写 <现有任务或 SPEC>。
复用已确认决定，指出仍会改变本轮结果的缺口。
这是方法参考；没有实际启用技能时，不声称已调用。
```

如要实际启用，按所用工具支持的方式与项目授权安装，再核对其依赖技能、自动触发、目录写入和交接行为。各工具入口不同，本文的技能名不是跨工具通用命令。采用优先级与冲突处理统一见 [AI 协作](../docs/AI_COLLABORATION.md#按需使用技能)，不在各卡重建一套规则。

## 版本更新与试用反馈

推荐版本核对日期：2026-09-10。沿双周学习节奏人工或通过既有提醒复查；本目录本身不创建定时任务，也不自动安装更新。新版本只有改变适用行为或暴露具体问题时才更新卡片，记录新旧版本、受影响条款及保留/调整/暂缓的理由。

实际使用后在原任务留下一个短反馈：遇到什么问题 → 用了哪个版本的什么方法 → 哪个决定或行为得到改善/仍有问题 → 实际验证与未知。只有有依据的变化才回写 SOP；一次任务观察不宣称普遍提升效率。无收益或造成重复劳动时可以撤回推荐，保留修改理由。
