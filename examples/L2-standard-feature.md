# 示例 SPEC：收藏项目

这是教学设计与交付说明示例，没有真实执行测试。所有背景为示例假设；实际项目应替换为检查过的来源。

## 来源与 Context

示例需求：用户希望在项目列表中快速找到常用项目。假设已有用户登录和项目可见性校验，但没有收藏记录。沿用现有权限模型，不改变项目授权。

## 目标与验收

- AC-01：当前有权访问的项目可收藏和取消，同一用户重复操作不产生重复记录。
- AC-02：重新登录后仍能看到自己的收藏；不能读取其他用户的收藏。
- AC-03：权限被移除后，收藏不会让用户绕过项目可见性校验。

本轮不做收藏排序、共享列表或消息通知。修改范围为收藏行为、相关接口与 UI，以及必要测试；具体路径由实际项目约定。

## 关键设计与理由

收藏关系使用用户与项目组合的唯一约束。查询时仍经过原有项目权限校验，避免收藏表成为另一份授权源；Client 提示操作失败并恢复显示，Server 保证幂等和权限边界。

两端设计可在此说明，暂不拆 CLIENT-SDD / SERVER-SDD。接口字段引用实际项目可执行定义；本示例不编造仓库链接。

## 验证安排

覆盖收藏/取消、重复请求、登录后持久化、其他用户访问、权限变化及 UI 失败反馈。权限相关分支需要适当独立评审；不因为增加评审就扩成完整文档包。

## 交付记录示意

如果实现已完成但还未验证权限撤销后的查询，应写明：“收藏主路径已实现；权限撤销行为尚未验证，AC-03 未确认，当前不能宣布任务完成。下一步补充该场景的实际测试与评审。”

当前示例没有执行代码或测试，也没有验收。它展示的是单份 SPEC 能同时记录设计与诚实的交付缺口；实际结果在本文件或关联交付 PR 中择一汇总。
