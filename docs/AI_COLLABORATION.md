# AI 协作与上下文连续性

AI 帮助分析、实施与验证，业务取舍、授权和风险接受由项目的实际责任人决定。采用何种 AI 工具由团队选择；原生工具负责模型调用、上下文管理、搜索、编辑与 Shell。本仓库不自建这些运行能力。

按问题跳转：[首次接入](#首次接入) · [日常开始](#开始工作) · [中断交接](#中断与交接) · [技能采用](#按需使用技能)。业务阶段与完成判断统一见 [完整流程](WORKFLOW.md)。

## 首次接入

首次接入由项目维护者或获授权的采用者准备，解决三个问题：AI 在哪个项目工作、从哪里读取约定、项目有哪些操作与交付边界。已有可用接入直接进入 [开始工作](#开始工作)，日常使用无须重复配置；换工具继续原任务使用 [交接记录](#中断与交接)。

### 选择所用工具的入口

| 使用方式 | 最小接入方式 |
|---|---|
| 在项目中使用 Codex | 在项目根目录的 `AGENTS.md` 合入必要指引，保留原有有效内容。Codex 启动时按项目目录层次发现指令；同目录 `AGENTS.override.md` 优先于 `AGENTS.md`，需核对实际生效来源 |
| 在项目中使用 Claude Code | 在根目录 `CLAUDE.md` 合入指引；若已有共用 `AGENTS.md`，按下方片段导入。Claude Code 不直接发现 `AGENTS.md` |
| 使用普通 ChatGPT / Claude 聊天，或工具没有项目文件访问能力 | 在允许的资料范围内提供项目约定、当前任务和本轮需要的规范内容，或使用已授权且确实可读取的连接。不要按仓库型工具的文件发现方式假定已接入 |

前两项依据 [Codex 项目指令说明](https://learn.chatgpt.com/docs/agent-configuration/agents-md) 和 [Claude Code 项目记忆说明](https://code.claude.com/docs/en/memory)，核对日期 2026-09-10。入口文件用于传递约定，不能替代工具权限配置、实际授权或测试。

### 项目约定共用一份

先查看项目已有的开发指南、指令和任务记录，只补缺口。团队同时使用两种仓库型工具时，可把共用指引维护在 `AGENTS.md`，让根目录 `CLAUDE.md` 导入它；仅使用 Claude Code 则可直接在 `CLAUDE.md` 维护，无须额外创建另一份。

下面是**适配片段**，不是新的完整项目模板。将占位符替换为真实可访问位置后，合入目标项目的现有入口；不要覆盖已有规则，也不要复制本 SOP 仓库维护用的 AGENTS.md。

```text
先读取项目约定：<现有开发指南或项目约定路径>。
通用流程采用 Workflow-SOP：<已核对的固定 commit/版本及可读取位置>。
开始任务时读取其中的 README，按当前问题读取流程与工程规则相关章节。
沿用当前任务的需求、决定和验收记录，只补影响实施或验证的缺口。
在本轮授权范围内推进；实际命令、资料边界与交付责任以项目约定为准。
来源读不到或检查未执行时说明缺口，不把生成文档视为任务完成。
```

共用文件应保持工具无关。以下内容放在同级 `CLAUDE.md` 的正文中；保留已有有效指令，检查是否与导入内容冲突：

```text
@AGENTS.md
```

实际文件中不要给这行加反引号或代码围栏，否则不会作为导入处理。此处只复用项目根指引；子目录专属规则仍需按所用工具核对，不能据此宣称两种工具的全部加载行为相同。

SOP 可从有权限的固定版本链接读取，也可由项目维护者准备固定版本的本地只读检出，并在项目约定登记位置和版本。私有链接、另一台机器的路径或仅写着“遵循 SOP”的文字都不保证 AI 能读到正文。引用不是自动导入：片段明确要求读取，首次使用还需确认读取结果。无需复制整套 SOP 到每个业务项目。

### 首次检查与后续使用

不确定接入是否正确时，在目标项目打开新会话，使用一次只读检查；指令变化后重开会话再核对。它不是每个任务的必经审批。

```text
请先只读检查当前项目的 AI 接入，不改文件、不安装依赖、不运行业务。
列出实际项目根目录、当前分支/工作副本，以及已读取的项目指令来源。
读取项目约定所指向的 Workflow-SOP，报告实际版本和本轮读取的文件；无法读取就说明。
指出现有任务/验收记录入口、验证命令及其出处、仍缺少的关键信息。
区分已观察事实和待确认事项，给出当前任务可继续的下一步。
```

将回答与实际工作目录、文件内容和可见读取记录对照；Claude Code 还可用 `/context` 查看 Memory files。AI 声称“已遵循”不等于加载或执行已经得到证明。只读检查发现的命令也未因此通过运行验证。

接入清楚后，把真实任务和授权交给 AI，按原流程实施、检查和交付。首次试用可选一个范围明确、容易验证的小改动，观察是否复用原记录、正确处理失败并给出实际证据；把偏差记回原任务。更换工具时带上当前决定、差异和证据，按交接规则核实后继续，无须复制聊天全文。

### 读不到或行为不符时

| 现象 | 先核对什么 | 修复与再确认 |
|---|---|---|
| 找错项目或读到旧约定 | 实际目录/工作树、SOP 版本、入口文件及上级/局部指令 | 在正确项目会话中读取选定版本；检查冲突的来源和适用范围，按授权修订，不直接删除团队规则 |
| Codex 未采用根指引 | 同目录 override、启动位置、指令是否过长 | 确认实际生效文件，压缩常驻指引并按需读正文；重启后复查来源 |
| Claude Code 未读共用约定 | 是否有 CLAUDE.md、导入是否放在正文、目标是否可读 | 修正入口并检查新会话；项目外导入可能需要工具许可，不绕过许可扩大访问 |
| 链接存在但正文不可读 | 私有仓库访问、网络、本地路径在当前环境是否存在 | 提供允许读取的固定版本内容；不把登录凭据写进指令文件 |
| 读到了却重复提问或生成整套文档 | 当前任务是否明确、指引/技能是否冲突、输入是否过多 | 保留一个权威记录和相关指引，修正冲突后用同一任务验证；不要再叠加一套流程 |

以上接入方式是基于官方说明的适配建议，本仓库的文档检查不证明目标机器已经成功加载。工具升级或出现漏加载、规则冲突时，按 [来源记录](SOURCES.md#ai-工具接入的定向核对) 复查受影响内容。

## 开始工作

项目已经接入时，直接描述任务或引用现有任务卡，写清本轮有变化的操作边界；可参考 [首页任务示例](../README.md#从这里开始)。沿用已记录的项目入口、SOP 版本、背景与决定，仅在缺失或变化时补齐；指令或访问条件变化时按上方接入说明核对。

先读取项目实际指令与相关工程事实，再选择流程章节或模板，避免一次加载整套资料。区分本轮是解释、讨论还是实施；已有明确授权时持续推进，不为常规步骤重复索取同一授权。

发现不了且会实质影响目标、范围或重要风险的事项才提问。可独立检查的信息自行核对。来源不可访问时说明限制，不假装已阅读。相关成熟案例可以帮助设计，但记录适用理由，不扩展需求。

## 讨论留下什么

把来源、工程上下文、已确认意图、重要决定与理由、验证预期和未知项写入当前任务或适用文档，具体载体见 [流程](WORKFLOW.md#约定与文档选择)。同一信息只维护一处。

已有信息足以支持当前实施时，直接继续工作；只有缺失部分才补记录。项目规则和当前任务未要求、也与当前问题无关的模板、技能卡和方法教程无需预先加载，不按目录逐个生成文档。

原生完整对话和模型内部推理不属于默认交付物。只留在聊天中的重要决定应及时写入可持续记录。讨论文件直接指导实施，不需要再层层生成 Prompt、固定 Agent 角色或阶段 JSON。

任务怎样从用户输入进入实现、验证和交付，见 [收藏功能的运行演练](../examples/L2-standard-feature.md#完整运行演练)。它使用本节的协作规则，不要求每阶段切换会话或重新发起指令。

## 自主执行与反馈

尽可能保持承担讨论与实施的上下文连续；是否采用同一原生会话、压缩、交接或独立协作由工具能力与任务决定，不强制绑定某个 session ID。

在已约定结果和授权边界内自主选择实现路径，依据编译、测试、实际运行和审查反馈迭代。汇报有意义的发现、完成行为、真实阻断和下一步；不要求每次编辑都填写状态，不反复生成已有文档的副本。

不要把模型自信当作测试结果，也不要将检查脚本成功解释为业务完成。代码与验证要求见 [工程规则](ENGINEERING_RULES.md)。确有收益时使用独立 AI 评审或并行任务，保持清楚的责任和集成范围；流程不预设固定数量的 Agent。

## 中断与交接

需要跨会话、换人或暂停时，在现有任务记录补充足够恢复的信息即可：

```text
目标与权威文档：
当前源码/配置/指令基线，以及未提交改动：
已完成行为与验证结果、证据位置：
重要决定、尚未解决的问题或外部影响：
下一步及仍适用的授权边界：
```

已有等价记录就引用，不创建另一套检查点目录。恢复时核对任务身份、约定版本、实际提交与未提交差异、未决项和已发生的外部动作，再决定继续还是重验。文件同名或账本标为完成，不足以证明是同一任务或结果仍有效；特别注意重复执行可能产生的外部影响。

遇到同一失败且没有新证据或进展时，停止盲目重试、报告已尝试内容并调整路线；正常迭代不按固定次数停止。缺少重要决定或越出授权时暂停受影响操作，无依赖的已授权工作可继续。取消或暂停不标为完成。

## 按需使用技能

[skills/](../skills/README.md) 是可选推荐与适配说明，帮助选择澄清、设计、拆任务、排查和评审方法；它不自动安装或加载工具，也不替代本 SOP。没有安装技能时，可读取指定来源并借鉴方法，但应称为参考阅读，不声称已调用技能。

在现有项目规则或任务中说明所选来源/版本、用途、必要差异与结果位置。外部技能的批准、派生代理、创建目录、执行命令和发布要求不自行扩大用户授权；目标项目的指令与实际授权优先。只为当前缺口选一个主要方法，避免多个技能重复访谈、各写一份规格或互相触发。

若已安装的技能会强制引入与项目不相容的流程，先使用其方法作为参考，或完成明确的本地适配后再启用；不能假定一句提示会关闭全部自动触发。是否安装及允许的工具由目标项目决定，推荐页面不构成安装授权。

阶段结果回到原任务或功能说明，按 [流程](WORKFLOW.md) 继续；技能自行宣告完成、生成模板或结束循环都不是业务通过证据。版本更新与试用反馈方法见 [推荐目录](../skills/README.md#版本更新与试用反馈)。

## 项目边界与配置

允许使用的 AI 服务、操作范围、凭据、资料外发及临时产物位置由项目明确。凭据和未经批准的敏感内容不进入通用模板、示例或聊天引用。过程缓存与长期工程文档分开，优先沿用已有存储设施，不规定磁盘盘符或数字目录体系。

团队接入时使用明确的规范版本与 [PROJECT-RULES](../templates/PROJECT-RULES.md) 中必要的项目差异。AI 无法自动发现外部规范时，在任务中提供可访问引用；不要声称复制某个文件就能适配所有 AI 工具。
