# Workflow-SOP

**让 AI 协作从一句需求走到可检查的交付。**

适用于与 AI 一起修复缺陷、开发功能和改造代码的开发者及协作团队，帮助你对齐三件事：

- **开始前**：要解决什么问题，项目现在是什么情况。
- **进行中**：怎样推进，哪些取舍需要你决定。
- **结束时**：改了什么、验证了什么、还有什么未完成。

这是一套可直接阅读使用的流程与模板，无需部署服务，也不要求先安装技能；可以配合 Codex、Claude Code 等工具使用。

## 从这里开始

**第一次把 SOP 用到项目？** 按 [接入指南](docs/AI_COLLABORATION.md#首次接入)，让 AI 能读到项目约定与选定版本的 SOP，再从一个小任务开始。

**项目已经接入？** 在项目会话里直接说明任务或引用现有任务卡。例如：

```text
请按项目约定修复标签首尾空白，保留中间空格和现有空值行为。
本轮修改代码并验证，不发布。完成后说明改动、验证结果和未完成项。
```

把示例换成你的实际任务与操作边界。已有的背景、版本和决定沿用原记录；只有变化或缺口才补充，无需每次重填接入信息。

## 完整链路

**说明目标 → 核对现状与方案 → 实现并验证 → 交付与反馈**

| 工作阶段 | 你会看到什么 |
|---|---|
| 理解问题与现状 | AI 核对项目与已有记录，找出影响实施的关键问题 |
| 明确结果与必要方案 | 对齐验收行为、必要方案和当前要做的一小步 |
| 小步实现与验证 | 根据实际检查结果修正改动，处理失败与变化 |
| 评审交付与反馈 | 按项目方式评审和交付，说明结果、证据及后续事项 |

你决定目标、业务取舍和授权边界；AI 在约定范围内推进。评审、验收与发布沿用项目责任安排。

想看失败后回到哪里、何时需要你参与、如何恢复中断任务，查看 [完整图解与判断规则](docs/WORKFLOW.md#完整链路)。

## 最后会得到什么

对于上面的标签修复，交付应能让你判断：是否只修改了首尾空白、是否检查了中间空格和空值、有什么尚未确认。例如：

```text
改动：<实际修改范围与代码位置>
验证：<实际检查的场景、结果与证据入口>
未完成：<未验证项、阻断或后续安排>
```

这是交付写法示意，没有执行该修复或测试。实际结果留在原任务或 PR 即可；需要具体参照时看 [小缺陷示例](examples/L1-bugfix.md) 或 [完整功能演练](examples/L2-standard-feature.md#完整运行演练)，不必另写一套报告。
