# Workflow-SOP

把这个仓库交给 AI，再提出任务。AI 按工作指南推进，并把功能的需求、实现和验证留在一份可持续修改的文档里。

## 从这里开始

在能访问目标项目的 AI 会话中发送下面这段话，替换任务内容即可：

```text
请读取 https://github.com/YIMO691/Workflow-SOP 的 README 和 docs/WORKFLOW.md，按指南完成任务。
先检查目标项目与已有记录，找到或建立对应功能说明，在实现和验证过程中持续更新。
任务：<描述要解决的问题，或提供已有提单>
```

任务有特殊操作边界时一并说明，已有项目文档直接沿用。私有仓库或项目读不到时，由 AI 说明具体缺口；提供获准读取的内容后继续。长期使用才需要配置 [工具接入](docs/AI_COLLABORATION.md)，首次使用无须先安装技能或部署服务。

## 给 AI 的执行入口

1. 读取 [工作指南](docs/WORKFLOW.md)，再检查目标项目实际指令与工程事实。此仓库的 `AGENTS.md` 用于维护本仓库，不复制为业务项目规范。
2. 找到已有功能文档；新功能没有合适记录时采用 [功能说明模板](templates/SPEC.md)。小修复可留在原提单或 PR。
3. 按授权实现、验证并更新受影响内容，交付改动、文档位置、实际结果和未完成项。需要时查 [工程规则](docs/ENGINEERING_RULES.md) 或 [技能推荐](skills/README.md)。

## 使用中会留下什么

**提单 → 核对需求与现状 → 实现并更新文档 → 验证与交付 → 后续沿原文档继续。**

功能说明只保留四部分：需求与边界、实现说明、验证与遗留、变更记录。人参与业务取舍和必要决定，AI 在授权范围内推进。看看 [同一文档怎样经历两次修改](examples/L2-standard-feature.md)。
